# Plan

A milestone is done only when `pnpm lint`, `pnpm typecheck`, `pnpm test` and the relevant e2e specs pass. The evidence (command output) is quoted in the milestone's commit body or in `docs/EVALUATION.md`.

| # | Milestone | Acceptance checks |
|---|---|---|
| M1 | Foundation: monorepo, cross-platform scripts, `pnpm dev`, CI, Drizzle schema and migrations from the ERD, `pnpm db:migrate`, design system | `pnpm install` is clean. `pnpm typecheck` and `pnpm lint` pass. Migrations apply on an empty database (PGlite in tests) with `pg_trgm` enabled. Audit and event triggers reject UPDATE/DELETE. `docs/design-system.md` exists. `.github/workflows/ci.yml` runs lint, typecheck and tests with a Postgres service. |
| M2 | Accounts, organisations, operations, areas (CSV import), relief items, join requests, RBAC | Integration tests cover register → approve → login for all five roles, lockout (C2), temporary password, org approval and rejection with reason, OA approval, observer invite, operation create and close, area CSV with rejected rows, duplicate area and item rejection, join request with no duplicates, and a cross-organisation access denial on every protected route. |
| M3 | Offline field core | Unit tests (fake-indexeddb) cover PIN wrap/unwrap, a wrong PIN, 5-attempt lock, recovery after online login, an encrypted-at-rest check (no plaintext name in IndexedDB), atomic save + outbox, local similarity, search by code, name and phone HMAC, distribution with zero-quantity rejection, the 24-hour void rule and the anonymous distribution. |
| M4 | Sync engine | Property tests (fast-check) cover arbitrary batch splits, drops, duplicates and reorderings → the server stores each event exactly once and devices converge. Integration tests cover resume, a revoked device rejected, a closed operation rejected, and pull cursor monotonicity. The UI shows the pending count and last sync time. |
| M5 | Conflicts, duplicates, flags, notifications | Injected same-field conflicts are detected at 100%. Different-field edits auto-merge. Resolution saves a new version. Duplicate jobs finish within 2 minutes after sync. Link and undo work. The 24-hour cross-org same-item flag works. Notifications are delivered to the right roles only. |
| M6 | Dashboard | Coverage labels with a zero-household area show "No records". Unserved list release → pull on the device. Household history. Audit search and CSV export, itself audited. Org, operation and observer reports in PDF and CSV, with the observer report containing no PII. |
| M7 | Privacy and operations | Masking per organisation. Retention job redacts and crypto-shreds, with an audit entry. Backup → restore round trip verified with row counts. Lockout auto-unlock. Device revocation blocks sync and login. |
| M8 | Simulation and evaluation | The device simulator plus a synthetic generator with labelled duplicates and conflicts produce `docs/EVALUATION.md`: precision ≥ 0.90, recall ≥ 0.80, 0 lost and 0 duplicated events under failure injection, 100% conflict detection, 500 events within 60 s at 400 kbps, coverage in < 3 s at 20k households, 50 concurrent devices, local save and search < 1 s at 5,000 households. |
| M9 | UI polish, i18n, a11y, README, seed, demo | Full bn/en key parity test. axe-core checks pass on key screens at 375 and 1440 px. `pnpm seed` creates all five demo roles. README covers Windows setup, architecture and the demo walkthrough. |
| M10 | Final audit | A line-by-line check of the PDF and addendum against the running app, the gaps fixed, `docs/FINAL-REPORT.md` and `docs/TRACEABILITY.md` complete. |
